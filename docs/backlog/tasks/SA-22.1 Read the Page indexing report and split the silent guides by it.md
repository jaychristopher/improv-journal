# SA-22.1 — Read the Page indexing report

## What was found

The site has 384 published pages and 32 old guides that have never surfaced,
and no reading in the repo says whether Google holds those pages at all. The
sample tables the audit reads are impressions, which a page that is not indexed
cannot have. The one report that answers the question sits behind a sign-in.

## Run

1. **Sign in and open the report.** Search Console → the property Ahrefs
   project 9723388 is connected to (the `sc-domain:physicsofconnection.com`
   domain property, or the `https://www.physicsofconnection.com/` prefix if
   that is the one verified) → Indexing → Pages. The direct URL for the domain
   property is `https://search.google.com/search-console/index?resource_id=sc-domain%3Aphysicsofconnection.com`.
2. **Record the two numbers and every reason.** Indexed count, not-indexed
   count, and each "Why pages aren't indexed" row with its count. Expected and
   uninteresting: 17 "Excluded by noindex tag" (search, one source, the picker's
   fifteen level-and-focus combinations), up to 32 "Page with redirect" (the
   library URLs that moved 2026-09-24), one "Not found (404)". Everything else
   is the finding — "Crawled – currently not indexed" and "Discovered –
   currently not indexed" above all.
3. **Export the not-indexed URLs** (the report's export button, one list per
   reason) and write them into `docs/seo/index-coverage-<date>.md` as a table:
   URL, reason, layer (guide / concept / library / hub / lesson / path). The
   layer column is what turns a list into a decision.
4. **Split the 32 silent guides by it.** The audit's "Never surfaced" list
   against the export: how many of the 32 are indexed and simply unranked, how
   many were crawled and declined, how many never crawled. Put the three counts
   in the doc, dated.
5. **Put the reading in the audit.** One line in `seo-audit.mjs` beside the
   "Never surfaced" block: indexed of 384, not-indexed by reason, the date, and
   the split from step 4. Move the date when it is re-read.
6. **Then, and only then, decide the lever.** Indexed and unranked: the current
   strategy stands. Crawled and declined on a guide: open a card for that list —
   internal weight and consolidation, never new pages. Discovered and not
   crawled: the sitemap and the hubs' links to those pages are the first thing
   to read.

## Verify

- `docs/seo/index-coverage-<date>.md` exists with the indexed count, every
  reason with its count, the URL table with a layer column, and the three-way
  split of the 32 silent guides.
- `npm run seo:audit` prints the reading with its date.
- The 17 noindex, the library redirects and the 404 are named as expected in
  the doc, so the next reader does not mistake them for a problem.

## Acceptance criteria

- The question "are the silent guides indexed?" has a dated, numeric answer in
  the repo, per guide.
- If any guide is "Crawled – currently not indexed", a card exists naming the
  list; if none is, the doc says so and the ranking strategy is confirmed in
  writing.

## Scoring

- **impact 5** — this is the one reading that decides which of two
  non-overlapping strategies the site should be running for 32 of its 40 old
  guides, 99k of claimed potential. Every card since SA-1 has assumed the
  answer.
- **radius 4** — it bears on the whole guide layer and the audit's central
  section. Not 5: it moves no page by itself.
- **opportunity 20**
- **complexity 1** — a signed-in report read, an export, and one table. The
  sign-in is why it is `human`.
- **roi 20.0** — the highest on the epic, because it is cheap and everything
  else waits on it.
