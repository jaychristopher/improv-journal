# SA-13.1 — Finish the coverage, stop hiding the diagrams

## What was found

Content diagrams counted on production, 2026-09-25, by inlined
`<svg role="img">`:

| Page                                           | Diagrams |
| ---------------------------------------------- | -------- |
| `/types-of-listening`                          | 4        |
| `/practice/techniques/pattern-break`           | 2        |
| `/how-it-works/cognitive-bandwidth`            | 1        |
| `/practice/vocabulary/base-reality`            | 1        |
| `/library/impro-johnstone`                     | 1        |
| `/threads/building-on-offers`                  | 1        |
| `/del-close`, `/theatre-games`                 | 1 each   |
| **all 11 `/paths/*`**                          | **0**    |
| **all 5 `/traditions/*`**                      | **0**    |
| `/conversation-starters`, `/21-questions-game` | 0        |

`public/images/` holds roughly 250 diagram SVGs. The markdown layers use them.
The route layer does not — and `Diagram.tsx` was written for exactly that case,
its own comment naming `/practice/formats`, `/how-it-works/principles` and
`/improv-games` as "components with no markdown prose, so the transform chain
never sees them". Paths and traditions are the same case and were not included.

The question-list zeros are a different matter and are probably correct: a
diagram of "21 questions to ask" would be decoration. This card does not ask for
them.

**And the diagrams never leave the page.** Every page's social image is a
generated text card:

```
og:image = /og?title=Cognitive+Bandwidth&eyebrow=How+It+Works
```

That is served on a page whose body contains a purpose-built diagram of exactly
what the page explains. Inlined SVG is not image-search inventory either, so a
library of 250 diagrams with genuinely descriptive titles is visible only to
someone already reading the page it sits on.

## What was checked and is fine

Recorded so this is not read as a broader complaint about the site's markup.

- **The diagram system itself is well built.** Build-time inlining, nothing
  shipped to the client, `<title>` as the accessible name because an inlined SVG
  has no `alt`, optional caption in the prose voice, and guards.
- **Structured data is in good shape.** 288 `Article` entities all declare an
  image; `og:image` is present on 385 of 386 pages; `Course` is on all 11 paths
  with `teaches`, `hasPart`, `syllabusSections` and `hasCourseInstance`;
  `PodcastEpisode` on 308. The types that are absent — `FAQPage`, `HowTo` —
  are absent correctly, because Google restricted or retired those rich results.
- **The search index is complete and cheap.** 366 documents covering every
  layer, 950KB on disk but 228KB over the wire under brotli.

## Run

1. **Give the 16 route pages their diagrams.** Use `Diagram.tsx`, the same way
   `/improv-games` already does — this is the pattern, not a new one. Paths are
   sequences and traditions are schools with distinct methods; both are the kind
   of thing the existing library already draws. Reuse an existing SVG wherever
   one fits before commissioning anything new.
2. **Make `og:image` prefer the page's own diagram.** Where a page has a primary
   diagram, compose the card from it rather than from title text alone. This is
   the cheapest half of the card: the assets exist, the OG route exists, and the
   descriptive `<title>` already written is the caption.
3. **Decide about image search deliberately, and probably decline it.** Real
   image-search inventory would mean raster derivatives referenced by `<img>`,
   which trades away the build-time inlining that was chosen on purpose. Weigh
   it, write the answer down, and do not quietly break the performance decision
   to chase a channel nobody has sized. A recorded "no" is the expected outcome.
4. **Leave the question-list pages alone.** They have no diagram because they do
   not need one.

## Verify

- Every path and every tradition page renders at least one content diagram.
- `og:image` on a page with a primary diagram uses it.
- No page gained an `<img>` unless step 3 concluded in favour, with reasoning
  recorded.
- `npm run check` green, including the diagram guards.
- `npm run seo:rendered` reports 0 critical.

## Outcome

**Done 2026-09-25.** Sixteen route pages have a diagram each, every card
now says what its page's diagram shows, and image search is declined with
the reason written where the card is made.

**Step 1 — sixteen diagrams, none commissioned.** `src/lib/route-diagrams.ts`
declares one existing diagram per path and per school page, keyed by route,
and `<RouteDiagram>` renders it through `Diagram.tsx` — the pattern
`/improv-games` already used, applied to the two layers that were the same
case and had been left out. Each choice depicts what the page teaches, and
the alt is the description the diagram already carries where it lives, so a
picture has one accessible name across the site:

The paths' diagram sits after the header, the schools' after the
orientation and before the guide link. `route-diagrams.test.ts` holds the
declaration complete for every path and tradition, every file present, and
— on a build — the diagram rendered and the card carrying it.

**Step 2 — the card composed from the diagram, in the one way that works.**
`ogImages` takes a third argument, the diagram's description, and the OG
route sets it under the title as a second line; the sixteen route pages pass
their declared diagram's alt, and every guide, lesson, library entry and
concept page passes the description of the first diagram in its body
(`firstContentDiagram`, beside `firstContentImage`). So a page with a
diagram now shares as its title plus one sentence of what the picture
shows, which is the descriptive `<title>` the card said was already written.

The picture itself is not on the card, and the reason is recorded in
`ogImages`: the diagrams are text-bearing SVGs styled by the page's CSS
classes (`.dg-ink`, `.dg-accent`, the page's typeface), and the card
renderer rasterises an SVG image without the page's stylesheet or its fonts,
so the labels — which are the diagram — would not survive the trip. A card
with an unlabelled drawing on it is worse than a card with a sentence.

**Step 3 — image search, declined.** Inventory for image search means raster
derivatives referenced by `<img>`, which trades away the build-time inlining
chosen on purpose — theme-aware, in the page's typeface, nothing shipped to
the client — for a channel nobody has sized. The Article markup already
lists a page's diagram first (`articleImages`), which is the honest amount
of image-search exposure the design allows. Recorded in the OG route.

**Step 4 — the question lists keep their zero.**

**What moved.** Sixteen pages gained a figure; every share card with a
diagram behind it gained a line. Three guards moved and are re-dated with
their accounts: `page-furniture` (paths 8 → 9 blocks above the article — the
diagram is content the count cannot tell from chrome, so it is named there),
`flight-share` (the paths' HTML and flight ceilings; an inlined SVG is in
both), and `article-image`, which needed a fix rather than a date: the
Article JSON-LD's card is built from the same inputs as the og:image, so
`ArticleJsonLd` and `LessonJsonLd` now take the diagram's description too
(`cardSub`) and the two cards agree on every page. Registers 25 done, 16
open; the SA-13 story closes with its only task. `npm run check` green, 282
files, 1,459 tests. `npm run seo:rendered`: the same two pre-existing
criticals, nothing new.
