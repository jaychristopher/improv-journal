# SA-18.1 — Track the queries the site actually has

## What was found

Three Ahrefs endpoints, 2026-09-25, project 9723388 / `physicsofconnection.com`:

| Endpoint                         | Result                                                     |
| -------------------------------- | ---------------------------------------------------------- |
| `site-explorer-metrics`          | `org_keywords: 0`, `org_traffic: 0`, `org_keywords_1_3: 0` |
| `site-explorer-organic-keywords` | empty                                                      |
| `management-project-keywords`    | empty                                                      |

Against Search Console over the same period: **7,755 impressions, 36 clicks**,
and four queries inside the top ten —

| Query                                                   | Position |
| ------------------------------------------------------- | -------- |
| will hines substack                                     | **6.0**  |
| "three listening modes" agreeing disagreeing being with | **6.9**  |
| retrospective justification meaning                     | **10.0** |
| pattern break                                           | **10.4** |

Ahrefs has no record of any of it, and the rank tracker on the project is empty.

## Why this is the third face of one problem

- **SA-10.1** — Ahrefs cannot see the site's _demand_. Seven of ten queries the
  site ranks for return null for `traffic_potential`, `difficulty` and
  `parent_topic`, because the terms are below the keyword index's floor.
- **SA-14.1** — Search Console shows the site's _aggregate_ but withholds
  queries below a privacy threshold, so the per-query table is 0.5% of it.
- **This card** — Ahrefs cannot see the site's _positions_ either.

Nineteen cards in this epic schedule a verification that reads the one table
affected by both problems. SA-16.1 found that table returns 12 pages from one
start date and 34 from another. None of those verifications can currently be
trusted.

**And the fix is the one instrument neither problem touches.** A rank tracker
does not consult a keyword index for volume — it checks where a domain ranks for
a string it is given. It works fine on terms Ahrefs has never heard of, which is
exactly this site's vocabulary. It is available on the project and it is empty.

## Run

1. **Load the queries GSC has already named.** `gsc-keywords` from 2026-02-01
   returns about 60 distinct queries with a page and a position each. They are
   first-party, they are what this site actually surfaces for, and they need no
   volume data to be tracked. Put them in the rank tracker. This is dashboard or
   API work, hence `mixed`.
2. **Add the terms the guides declare but have never surfaced for.** The six on
   `/viewpoints` are the sharp case — SA-17.1 shows the guide taking zero
   impressions on all six while the book citation takes them. Tracking both
   pages against those strings is how that card gets verified at all.
3. **Do not add keywords nobody has evidence for.** The temptation is to load
   all 317 declared keywords. Most have never surfaced, tracking has a per-
   keyword cost, and a tracker full of terms the site does not rank for measures
   nothing. Start with the sixty that exist plus SA-17.1's six.
4. **Point the audit at it.** `seo-audit.mjs` carries a hand-dated GSC block
   that a person refreshes. Add a rank-tracker reading beside it, so "did that
   change work?" has an answer that does not depend on GSC's threshold or on
   which start date somebody picked.
5. **Write the verification rule down once.** Every card's Verify section should
   name the same instrument. Today they variously say "re-read gsc-pages",
   "re-read gsc-keywords" and "watch position" — and SA-14.1 already established
   that position is the wrong headline metric. One rule, recorded in CLAUDE.md
   or the audit, is worth more than six restatements.

## Verify

- The rank tracker holds the ~60 GSC queries plus SA-17.1's six declared terms,
  and returns positions for them.
- `npm run seo:audit` reports a rank-tracker reading, dated.
- The epic's cards reference one named verification instrument rather than
  several.
- No keyword was added that has neither a GSC impression nor a declaration in a
  guide's frontmatter.

## Scoring

- **impact 3** — it brings no visitor and moves no page, which caps it. What it
  does is make the difference between a backlog whose outcomes can be checked
  and one whose cannot: nineteen cards currently promise a verification against
  an instrument shown to be both 0.5% complete and window-dependent. Not 4:
  SA-14.1 scores 4 because it corrected numbers already being acted on, whereas
  this enables future measurement. Not 2: three endpoints agree, the gap is
  total rather than partial, and the remedy is the one tool neither existing
  blindness affects.
- **radius 5** — it is the verification substrate for every card in the epic.
  Nothing has wider reach than the thing the rest is checked by; the same
  argument SA-14.1 used.
- **opportunity 15**
- **complexity 2** — loading a keyword list into a rank tracker and printing its
  reading. No code paths, no content, no URLs. Not 1: step 1 is account work an
  agent cannot finish alone, and step 3 exists because the obvious move —
  tracking all 317 declared keywords — costs money per keyword and would measure
  mostly nothing.
- **roi 7.5** — behind SA-14.1's 10.0 and just behind SA-1.1 and SA-16.1 at 8.0.
  That ordering is right: correct the numbers already in use first, then do the
  two cards that convert something, and set up the instrument alongside them so
  their 30-day re-reads have somewhere to land.
